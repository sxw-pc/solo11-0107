# 建仓需求补充 v2：主体授权与导出追索

此补充对应既有项目的源码增量。原 seed 及其历史来源保留，不追改数据库记录。原有快照、事务回放、目标修复、消费者发布和报告命令的输入与输出契约继续有效。

## 业务对象与持久化状态

- `data_subject` 与 `subject_key` 冻结数据主体对回放业务键的归属；同一键不能转派给第二主体。
- `consent_source` 保留授权文件原始字节、哈希和拒绝原因；`consent_event` 按主体、用途、版本记录 grant/revoke、有效水位和证明摘要。相同版本不得改变决定。
- `controlled_export`、`export_row` 与 `export_exclusion` 保存指定回放运行、用途、收件人、实际导出值和逐键排除原因。导出仅消费 `visible_row` 的“存在”状态及有效授权。
- `export_recall` 和 `recall_receipt` 保存迟到撤销对已发值副本的追索及原收件人签收；历史导出行不被重写。

## 决策链

1. 原始授权证据先建立主体到键归属及用途版本；同一主体可对不同用途分别授权。
2. 导出按回放水位选择对应授权版本。无授权、撤销、过期、未映射和回放不可见分别持久化排除原因。
3. 撤销事件可迟到写入，其有效水位可覆盖之前的回放运行。导入撤销的事务同时为旧导出逐键形成待召回记录；`export-audit` 可幂等复核。新导出不再包含该值。
4. 收件人回执只关闭对应召回，错误收件人或回执证明冲突不能关闭。重复审计和重复一致回执不增加追索事件。

## 独立边界与可复现检查

`python -m cdcverdict demo-consent` 展示授权→旧导出→迟到撤销→召回→新导出排除→原收件人回执。`tests/test_consent.py::test_release_gate_can_be_ready_while_export_recall_pending` 是最小分离反例：原消费者目标发布闸门仍 ready，主体撤销却使旧值导出待召回、新值导出为空。该结果与订阅游标、envelope 投递或报告发布无因果替代关系。

`python -m pytest -q` 覆盖正常、用途隔离、版本冲突、归属冲突、未来撤销、迟到撤销、再授权、重复审计及回执错误/恢复。必要时以 `export-report` 检查每个导出的行、排除原因和召回状态。
